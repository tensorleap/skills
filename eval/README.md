# eval — blind skill-eval harness

Tests the `tensorleap-integration-creation` skill by running it, blind, against
real ML repos: for each fixture an agent must author a complete Tensorleap
integration for a *pre-integration* repo it has never seen, push it, and get a
**successful evaluate** on a local Tensorleap server.

**A fixture PASSES when, on the platform, its build Push reaches `FINISHED` AND
its Evaluate reaches `FINISHED`.** Nothing less counts.

This is repo tooling (like `build/`), not part of the shipped skill — it is
never packaged into `dist/`.

---

## Prerequisites

- **bash 4+** (`brew install bash` — macOS ships 3.2, too old). Run scripts with
  `/opt/homebrew/bin/bash`.
- **ripgrep, jq, git** on PATH (`brew install ripgrep jq git`).
- **poetry** + **git-lfs** (fixtures hydrate model files via LFS and build a
  poetry env).
- A reachable **Tensorleap server** + non-interactive auth (`leapdev` on a local
  dev install, or `leap --apiUrl … --apiKey …` for a remote).
- For the **private** fixtures only: AWS creds (SSO) and access to the
  `Tensorleap-hub` private repos. The public fixtures (incl. `cifar10_resnet`)
  need none of this.

## Operational rules (each one cost us a full debugging cycle)

These are not style preferences — every one of them was learned by losing a run
to it. `run.sh` enforces them in code; they are spelled out here so you
understand *why* a run behaves the way it does and can reproduce a run by hand.

### 1. `CLAUDE_CONFIG_DIR` must be UNSET — not empty

If `CLAUDE_CONFIG_DIR` is set to `""`, the Claude CLI resolves a phantom config
directory and **the integration plugin becomes invisible** — the agent silently
runs without the skill under test, and the whole eval is meaningless. It must be
*unset*, not blanked. `run.sh` launches the agent with `env -u CLAUDE_CONFIG_DIR`;
by hand, run `unset CLAUDE_CONFIG_DIR` in the shell first.

### 2. Use `leapdev`, never bare `leap`

Bare `leap` may be pointed at a **production** Tensorleap server — a blind eval
must never touch prod. Every Tensorleap command in a run must go through
`leapdev` (local dev) or an explicitly-configured remote. `run.sh` puts a
`leap` → `leapdev` shim first on `PATH` so even if the agent types `leap`, it
hits the dev server. To set the shim up by hand:

```bash
mkdir -p ~/tl-shim
printf '#!/usr/bin/env bash\nexec leapdev "$@"\n' > ~/tl-shim/leap
chmod +x ~/tl-shim/leap
export PATH="$HOME/tl-shim:$PATH"
```

### 3. Install the skill and make it the ONLY Tensorleap skill

If both the marketplace plugin *and* a local copy of the skill are present, the
agent sees **two** skills and may load the wrong one — again invalidating the
eval. Ship exactly one. Either install the plugin and remove any local copy:

```bash
claude plugin marketplace add tensorleap/skills
claude plugin install integration@tensorleap -s user
rm -rf ~/.claude/skills/tensorleap-integration-creation   # remove any shadowing local copy
```

…or, to test an un-published working copy, pass the built dist directly with
`--plugin-dir dist/claude/integration` (generated by `python build/generate.py`)
and make sure no other copy is installed. `run.sh` takes a `--plugin-dir` and
verifies exactly one Tensorleap skill is visible before it starts.

### 4. One push at a time — fixtures run strictly sequentially

The local Tensorleap server cannot handle two concurrent push/evaluate cycles;
running two fixtures at once corrupts both. Never parallelize. `run.sh` (and the
`run_all.sh` wrapper) gate each fixture on the previous fixture's Evaluate
reaching a terminal state before starting the next.

### 5. (Historical) foreground-push — no longer needed

Earlier headless (`claude -p`) drivers had to run the push in the *foreground*:
in print mode the session exits the instant the agent yields, so a backgrounded
`push --eval` was reaped **after the push but before the evaluate step** — you
got a Push with no Evaluate. `run.sh` avoids this entirely by driving an
**interactive** session over tmux (no `-p`): the REPL does not exit on the
agent's final answer, background work survives, and completion wakes the agent.
So the foreground rule is deliberately gone — but understand the reap, because
the same premature-completion trap can bite any background wrapper around a push.

## Quick start (one fixture)

From this `eval/` directory:

```bash
BASH=/opt/homebrew/bin/bash

# 1. Build the blind copy (+ its poetry env). Slow the first time (installs deps).
$BASH prepare.sh --fixture cifar10_resnet --bootstrap-poetry

# 2. Prove it is actually blind (no solution left, git history scrubbed).
$BASH verify.sh --fixture cifar10_resnet

# 3. Drive the agent to author + push + evaluate.   [runner — not built yet]
$BASH run.sh --fixture cifar10_resnet

# → eval/reports/cifar10_resnet.md   (tokens, cost, pass/fail)   [report — not built yet]
```

`cifar10_resnet` is the recommended first run: it is a **public** fixture (CIFAR
downloads at runtime), so it needs no private creds and proves the loop.

See which fixtures you can choose from (ids + which need staged data/creds):

```bash
bash run_all.sh --list
```

## What each piece does

| File | Role |
|------|------|
| `manifest.json` | The fixture corpus: repo URL, pinned commit, what to strip, data prerequisites. |
| `prepare.sh` | Clones the repo at its pinned commit, strips the integration files, **scrubs git to a single rootless commit with no remote** (so the solution can't be recovered), and builds the poetry env. Output → `.fixtures/<id>/pre`. |
| `verify.sh` | Asserts the `pre` copy is genuinely blind: no root-level `leap*` files, no code importing `code_loader`, single rootless commit, no remote. **Do not run the agent unless this passes.** |
| `bootstrap_poetry.sh` | Sets up a fixture's poetry env (invoked by `prepare.sh --bootstrap-poetry`). |
| `lib/reset_lib.sh` | Shared helpers used by the above. |
| `run.sh` | *(next)* Drives an interactive Claude session (tmux) to run the skill, then tracks the Evaluate to a terminal state. |
| `report.py` | *(next)* Emits the per-run report — tokens, cost, where it got stuck, pass/fail. |

Regenerated / machine-local (gitignored, never committed): `.fixtures/`,
`reports/`, `runtime_prerequisites.local.json`.

## Blindness — what it does and does not guarantee

`prepare.sh` + `verify.sh` block the agent from recovering the answer **locally**
(no `git log`, no remote, no leftover leap files) and a deny-list blocks reading
sibling repos and other sessions' memory.

They do **not** block the open web or the model's training memory. 7 of the 10
source repos are public, so their reference integration is a web fetch (or a
recalled well-known model) away. Treat a green run on those as "the skill still
produces a working integration," not proof it derived the answer unaided. A
future hardening step is network egress control during the agent run.

---

## Privacy

The public fixtures' repos are public. The private fixtures' **repos and data
stay access-gated** — the harness clones/stages them at runtime from their
private homes into gitignored working dirs; nothing customer-owned is ever
committed here. The manifest currently lists all fixtures' pointers (names, not
credentials); whether to move the private portion out of this public repo is an
open decision.
